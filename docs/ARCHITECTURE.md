# 架构与数据规则

## 事实来源

唯一世界状态是 `World`，不依赖 React 组件生命周期。`store.ts` 负责调度与通知，React 只读世界并提交受控操作。所有随机模拟来自保存的 xorshift32 状态，渲染动画只读状态，不能推进事件。

`World.time` 是连续游戏时间，`simulatedUntil` 是已完成的 5 分钟边界。一次推进与拆成多个推进得到相同结果。逻辑节点运行顺序：跨日整理与账本 → 需求变化 → NPC 独立位置 → 到期故事 → 活动结束结算 → Utility AI 选下一项活动。活动开始/结束和短期建议保存在状态中。

游戏日历用 UTC 数值表达“浮动本地时间”。只在创建时读取当前系统的年月日，初始化到 08:00；之后游戏日历不因系统时区变化而重写。玩家日记则使用现实当地日期。

## 时间与离线

`SimulationClock.catchUp` 计算 `max(0, now - lastReal) * speed`，并应用用户选择的游戏日上限。暂停仍更新现实基准，恢复后不会补算暂停期间。系统时间回拨保留现实时间高水位，直到时钟追上，防止重复收入和事件。

在线定时器、休眠恢复、窗口重新可见、应用启动全部调用相同的 catchUp。离线不渲染帧；30 天只有 8,640 个固定步，测试中不造成启动卡顿。完整事件按上限滚动保留，每个游戏日生成一篇正式日记。

极端向前改动系统时间会触发上限，并把现实高水位移到新时间；再回拨时会等待追上。若用户确实要修正这一时间锚点，可导出后重新导入，明确重置现实基准。此行为属于反重放策略，避免自动重复结算。

## 活动与事件

行为分数来自人格、需求、职业作息、兴趣、目标、家具、近期事件、关系、重要地点记忆、模拟天气、最近活动和确定性随机因素。持续时间最少 15 分钟；极低精力/极高饥饿可以打断。

`EventEngine` 筛选活动、职业、关系、日历与冷却条件后抽取内容。`EventChainEngine` 保存阶段、最早触发时间、起源事件和结局，等待选择不会阻塞模拟。重要职业/住房/恋爱选择始终等待明确操作；自主模式只自动处理低风险的小故事结尾。“偶尔征求”约一半故事结尾自行决定，“重要事情询问”保留故事末尾询问。

`NPCSimulationEngine` 独立更新 NPC 的地点、时段计划与日级生活记忆。相遇需要同一场景；五维关系分别更新。恋爱需要多次愉快相处、信任、亲密、浪漫倾向与双方意愿，不会仅根据一个好感值确认。

## 收入与跨日幂等

工作满至少 180 游戏分钟才结算当日职业收入，以 `lastSalaryDay` 去重；便利店夜班按结束班次的日期归属。住房费用用 `lastRentDay` 去重。所有资金变化经过 `transact`，有来源和时间戳。金钱与需求有边界，人物能在余额不足时采用最低成本生活，不形成强制生存惩罚。

跨日只为前一个日期调用 `closeDay`，同日期已有日记就不重复生成。日记引用真实事件 ID。超过事件保留窗口的原始事件可能被裁剪，但日记正文和引用 ID 保留。

## 玩家信息边界

聊天数组只在 UI 会话内存在，不保存完整对话。`rememberPlayer` 只在用户明确勾选后调用；明确拒绝记忆的文本仍不保存。保存的内容是用户原话，不从言外之意推断现实事实。去重、条数上限与删除都可测试。

玩家日记草稿只引用授权记忆与真实活动记录。计划与返回时间均保留“未确认”，只有确认后的实际分钟数写成已完成事实。手写日记独立于记忆，删除记忆不秘密改写用户自己的日记，界面会提示必要时自行修改引用。

当前没有外部语言模型，也没有远程请求。未来模型接入只能生成表达候选，不能接触存档写入/系统操作接口。世界事实始终由本地引擎决定。

## 持久化与权限

桌面主进程使用固定目录，不接受 renderer 提供的任意文件路径。导入/导出路径只能来自系统文件对话框。IPC 验证 sender 和 mainFrame；renderer 开启 contextIsolation + sandbox，关闭 Node。阻止网页跳转与 window.open，CSP 不允许远程脚本和图片。

完整世界先经 Zod 与时间/重复记录约束校验，再序列化为带版本和 SHA-256 的封套。写入在串行队列执行，上一份有效主档进入备份，当前档写临时文件并 fsync 后 rename。载入优先主档，失败后读取备份，两个都失败时报告而不伪装成新玩家。没有原生数据库模块或 postinstall 编译负担。

## 测试重点

固定步长与倍率一致性、暂停/回拨、跨夜/夜班、极长离线边界、工资幂等、真实日记来源、NPC 独立生活、全部 15 条链、重大选择等待、双方关系意愿、玩家隐私、实际专注时长、导入拒绝、并发保存、主档损坏恢复，以及真实 Electron UI 的完整链路。
