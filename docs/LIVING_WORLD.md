# Living World 0.2 — 实现与使用

本扩展在原有 TypeScript 固定步长引擎、React/Canvas 界面、Electron 与浏览器存档之上实现。没有新建替代项目，没有连接云端 AI。网页版继续使用原地址：

https://lumosnox-bamboo.github.io/another-today/

## 开始体验

1. 原有角色可以直接继续。首次读取旧 `version: 1` 存档时补齐 `living` 扩展，不改角色、时间、原记忆和原剧情 ID。
2. “今天”会出现基于实际经历的主动分享卡片。可以聊，也可以稍后再聊；忽略不扣好感。
3. “一起专注”现在记录学习、阅读、工作、休息、运动、睡前回顾或自定义事项。小人继续独立安排生活，返回时间不等于玩家实际活动时长。
4. 新增“世界”入口：看小镇新闻与居民近况，送礼物、查看和赠送作品，跟进长线故事，观察习惯和愿望。
5. “设置 → 交流与季节”可以关闭主动交流、免打扰、调整每日提示上限，或选择世界/现实季节日历。
6. “人生档案”可选择重要事件，沿真实因果记录回看礼物、作品、相遇和后续变化。

## 系统接入

| 系统 | 已接入的行为与状态 |
|---|---|
| InteractionScheduler | 现实日预算；人格、心情、压力、熟悉度、最近事件、上次交流、专注、通知设置和免打扰；默认普通 2 次、总计 4 次，普通可设 0–3 次；夜间 22:00–08:00 安静。只使用游戏内提示，没有系统推送。 |
| SharedActivityEngine | 沿用 `playerActivities`；新增类型、预计结束、游戏时间起止、按 5 分钟模拟步累计的小人活动、玩家确认后生成的交流。 |
| LifeInteractionEngine | 主动询问生活、朋友、收藏、作品、烦恼、心事、过去、城市、共同经历；生活建议影响短期行为权重，情绪支持有每日作用上限。 |
| GiftEngine | 30 件礼物、10 类；按人格/兴趣产生不同反应；实际使用增长兴趣倾向、植物成长和后续事件；不直接加玩家好感。 |
| HabitEngine | 40 个原型，按日期、活动、环境和人格形成/强化/弱化/重新形成；夜班、雨天、周末图书馆等习惯有事实条件；影响选择、日记和部分动作。 |
| SecretEngine | 20 个原型；生成后偏向相关活动，真实练习累计进度；准备程度与信任共同决定揭晓；有完成、过期、分享与记忆。 |
| NPCSimulationEngine / NPCLifeEngine | 6 位核心、8 位普通、4 位背景居民；不同日级更新强度；持久化项目、工作、兴趣、住处和居民之间的友谊、分歧、恋爱/分手；双方关系排他性检查。 |
| TownNewsEngine | 50 个模板；实际开始的社区安排、机会与维修；影响活动权重、NPC 去处和作品展示。居民新闻必须引用实际居民变化事件。 |
| SeasonEngine | 四季、季节景色、冬季衣物、秋叶/雪、季节活动偏好、NPC 去处、植物成长与节日。独立世界历随游戏推进；现实模式在时钟结算时同步现实日期，不把加速模拟当作未来现实季节。 |
| EventEngine | 220 个基础事件、20 类；活动/职业/关系/地点/世界状态条件、人格结果分支、权重、冷却。对重复较多的模板降低权重，避免用事件数量代替生活深度。 |
| StoryArcEngine | 15 条新增故事；起点、两个中间状态、关键建议窗口、两种结局；数天至数月；必须实际到达相关地点才推进，支持暂停、错过、恢复、提前结束。新故事最多同时 2 条，新旧合计最多 3 条。 |
| RegretAndDreamEngine | 原始人生目标沿用已有真实进度；新愿望来自实际活动；放下、回望、重新尝试和实现写入记忆/档案。 |
| CreationEngine | 绘画、写作、摄影、音乐四类；多次实际创作/摄影活动积累；原创程序化像素图案、事实来源文字与可播放短旋律；作品可赠予认识的居民，可借社区机会展示。 |
| PlayerLinkedEventEngine | 只引用主动授权保存的玩家原话；目标询问、阅读/音乐话题、本人明确提供的月日生日；删除记忆同步移除派生提醒。不会推断考试结果、完成情况或他人生日属于玩家。 |
| EventCausalityGraph | 重要事件快照、触发原因、人物、直接结果、父事件、记忆引用。可追溯礼物 → 创作 → 展示 → 居民相遇等真实路线。 |
| ContentValidator / LivingValidator | 唯一 ID、合法活动/场景/人格/职业关系 gate、有效效果/权重/冷却、有效后继与无循环；存档中的目录引用、关系、作品时间和因果图一致性。 |

## 数据与兼容性

- 存档外层及桌面校验格式仍为 `version: 1`。新增 `living.revision: 1`，通过 Zod 默认值迁移。旧 `playerActivities` 的新字段均为可选，旧档不会虚构已经发生的共同活动。
- 在线版仍只在当前浏览器保存；没有上传玩家存档、聊天或日记的服务器。Electron 保留原子写入与上一版备份。
- 新版读旧档。不要使用旧版应用覆盖已经保存扩展内容的存档；旧版并不了解新增字段。
- 近期完整作品最多 60 件；满后保留最近作品，创作继续。新闻最多 100 条、主动分享 60 条、习惯历史 150 条、因果快照 600 条。重要根节点尽量保留；档案不是无限历史数据库，建议定期导出完整存档。
- 所有模拟随机选择沿用存档中的确定性随机状态。长时间离线仍遵循原来 1/7/30 游戏日补算上限。
- 现实同步季节在返回时同步当前日期；不为现实中错过的每个节日补发提示。切换模式不重复结算已经记录的季节/节日。
- 日历与新闻按真实状态更新，仍属于有限规则模拟；NPC 的简化项目进度不等同于为 18 位居民各运行一个完整主角引擎。

## 内容阶段

本次完成第一阶段 **220 个基础事件**；组合使用场景、真实参与人、人格分支、状态条件与历史来源。500+ 基础事件和 2000–5000 经过编辑的变体仍为后续内容阶段，未通过改名、复制文本或静态假事件计数。

保留了原有 15 条短事件链，另加需求指定的 15 条长线故事。一次性长故事不会无限重复；社区事件、居民变化、习惯与创作会继续运行。

## 验证

```sh
npm test
npm run audit:living
npm run test:web
npm run test:e2e
npm run format:check
```

`audit:living` 运行 100 个种子 × 30 日：其中 90 个完全无人干预，10 个只在开始收到一份礼物。每游戏小时采样需求范围，每日验证完整存档；统计普通事件分布、重复比例、重要事件、NPC 关系和职业变化、习惯、作品、日记与存档大小。

另运行五人格 × 五个配对种子 × 30 日；除人格外，职业、兴趣、起始世界一致。检查社交、工作、创作的方向差异，并保存活动分布、关系、习惯、日记和剧情结果。

结果：`docs/LIVING_WORLD_AUDIT.json`；本轮验收说明：`docs/LIVING_WORLD_TEST_REPORT.md`；逐组开发记录：根目录 `DEVELOPMENT_PROGRESS.md`。
